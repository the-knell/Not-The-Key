# Phase 2 — Backup blast radius at core 2026.11.0

- Backup system: components/backup, securetar==2026.10.0 (manifest). Backups are tar archives; inner per-folder tars (homeassistant.tar.gz = the config folder, ssl, addons, share, media...) are encrypted with SecureTar when protected; backup.json metadata rewritten protected:true/false (util.py encrypt_backup/_encrypt_backup, decrypt path mirror).
- Encryption default: AgentConfig.protected default True when absent (config.py:208 agent_config.get("protected", True)); per-agent can be set False for non-cloud agents (docs: per-location toggle). Cloud agent hard-requires protection: components/cloud/backup.py:118-119 raises "Cloud backups must be protected". Automatic backups: configured with a password (automatic_backups_configured := create_backup.password is not None, store migration 1.5).
- WHERE THE KEY LIVES — the blast-radius fact: the automatic-backup password is persisted in PLAINTEXT in .storage/backup. Code admits it in a comment: _BackupStore.__init__ (components/backup/store.py:39-43): Store(..., private=True) with comment "The store persists the automatic backup password in plaintext." CreateBackupConfig.password round-trips to StoredCreateBackupConfig["password"] (config.py:652,663,676). File mode 0600 (private store; minor-version 1.8 note says stores rewritten once with mode 0600).
- .storage/auth INSIDE backups: a backup's homeassistant content is the config folder (docs C8: "Home Assistant settings ... include the config folder"; restore writes it back and C8: post-restore logins use the password "as they were at the time the backup was taken" — i.e., the auth state restores wholesale). .storage/ is inside the config folder, so .storage/auth and .storage/backup (and .storage/auth_provider.homeassistant, .cloud/production_auth.json, core.config_entries with webhook IDs) ride inside every homeassistant backup, under the SecureTar encryption when protected.
- NET ANSWER: encryption-by-default is real, but the decrypt password for every automatic backup sits in plaintext in the same directory the backup archives. One read of a live config dir yields (a) all token secrets directly and (b) the backup password, which decrypts every exported automatic backup the user has ever made — and each restored/decrypted backup independently contains the same .storage/auth. For UNPROTECTED per-agent backups (user-disabled), the archive itself is directly readable. The emergency-kit model (docs C9: vendor does not hold the key) is true of the vendor; it is not true that the key is absent from the installation — it is stored next to the data it protects.
- Not verified in code: SecureTar KDF internals (external package securetar 2026.10.0, not read); Supervisor-side tar assembly (separate repo). The core-side inclusion chain (config folder incl .storage) is docs-stated + restore-path code (manager async_restore_backup with restore_homeassistant).
